02 Código único do jogo

Um único código cuida do caixa, do estoque, do troco, das promoções e das rotas de delivery.

  1. Copie todo o código abaixo para Principal, preservando a indentação.
  2. Pare os outros scripts e clique em Rodar com Principal aberto. Mantenha apenas este arquivo em execução, inclusive depois de liberar o delivery.
  3. Avance os diálogos dos clientes até fechar o resultado de cada venda. A recompensa e o registro da venda chegam no fechamento.
Principal · Python-like
def buscar(mapa, entrega):
    origem = entrega["origem"]
    destino = entrega["destino"]
    largura = len(mapa[0])
    fila = [origem]
    inicio = 0
    pais = {}
    mapa[origem[0]][origem[1]] = 0
    achou = False
    while inicio < len(fila) and not achou:
        atual = fila[inicio]
        inicio = inicio + 1
        if atual[0] == destino[0] and atual[1] == destino[1]:
            achou = True
        else:
            for passo in [[-1, 0], [1, 0], [0, -1], [0, 1]]:
                linha = atual[0] + passo[0]
                coluna = atual[1] + passo[1]
                if linha >= 0 and linha < len(mapa) and coluna >= 0 and coluna < largura:
                    if mapa[linha][coluna] == 1:
                        proxima = [linha, coluna]
                        pais[linha * largura + coluna] = atual
                        fila.append(proxima)
                        mapa[linha][coluna] = 0
    rota = []
    if achou:
        atual = destino
        while atual[0] != origem[0] or atual[1] != origem[1]:
            rota = [atual] + rota
            atual = pais[atual[0] * largura + atual[1]]
        rota = [origem] + rota
    return rota

Versão integral: baixar código único completo. O código funciona na linguagem do jogo; não precisa instalar Python.

O que ainda exige sua ação: comprar os upgrades na interface e avançar os diálogos dos clientes. A linguagem atual não possui comandos para essas ações. O mesmo código funciona desde o início e assume as entregas assim que você comprar Delivery Online; não precisa editar nem reiniciar o script.

Quando esta etapa está pronta?

Aguarde a mensagem “Desafio Mercado Automatizado concluído!”. Ela exige três vendas válidas com uma automação ativa, uma compra por script e a recuperação real de um produto que caiu abaixo do mínimo após uma venda. Pode levar mais de três clientes até todos os requisitos acontecerem.

Não compre tudo no início. Uma partida nova começa com R$180 e cinco unidades de cada produto. O script só compra um lote quando o estoque cai abaixo do mínimo, verifica espaço e saldo e tenta novamente nos próximos ciclos se faltar dinheiro.
Como o script funciona

sensor() verifica se há cliente; input() lê o pedido uma vez. O script percorre o carrinho, aplica as ofertas do atendimento e envia a resposta. Depois consulta o estoque e repõe um lote dos itens abaixo do mínimo. No mesmo ciclo, consulta a entrega e calcula a rota por BFS se houver um pedido. Antes do desbloqueio, a consulta retorna sem pedido e o mercado continua funcionando. wait(0.2) evita verificações contínuas sem pausa. Antes dos upgrades, as promoções retornam uma lista vazia e o pedido ainda não contém pagamento.

O arredondamento usa // porque esta linguagem não oferece round(). O código arredonda valores não negativos para centavos, como os totais e trocos válidos do jogo.

03 Liberar o troco

Junte pelo menos R$250 e compre Troco automático.

  1. Mantenha o script Principal rodando e conclua os atendimentos até o saldo atingir R$250.
  2. Na loja de upgrades, compre Troco automático por R$120. O jogo exige R$250 de saldo antes da compra, deixando pelo menos R$130.
  3. Continue usando exatamente o código da etapa 02. Ele detecta o campo pagamento e passa a enviar total e troco, nessa ordem.
Não faça outro input(). O pagamento vem no mesmo dicionário do carrinho. Uma segunda leitura não devolve o pagamento.

Confira com um exemplo

Dois arrozes a R$3 e um feijão a R$4 somam R$10. Com pagamento de R$20, a resposta é send(10, 10). O script calcula os valores reais de cada cliente.

O saldo cresce pelas recompensas dos atendimentos e cai com reposições. Não existe um número fixo de clientes para chegar ao próximo upgrade.

Fontes: preço e reserva, formato do pedido, preços dos produtos.

04 Aplicar promoções

Junte pelo menos R$300 e compre Sistema de promoções.

  1. Depois de comprar o troco, continue atendendo até ter R$300.
  2. Compre Sistema de promoções por R$160. A reserva mínima deixa pelo menos R$140 após a compra.
  3. Mantenha o mesmo script da etapa 02. Ele consulta promocoes() a cada atendimento e trata todos os produtos e os dois tipos de oferta.
Regras que o código já resolve
OfertaCálculoExemplo
Leve X, pague YGrupos completos pagam Y; as sobras pagam preço normal.7 morangos, leve 3 pague 2: paga 5 unidades, R$25.

As ofertas mudam entre clientes. Podem existir uma ou duas regras, sempre para produtos diferentes. Não aplique um desconto geral de 10%: essa regra é de conteúdo legado. O estoque perde todas as unidades levadas, inclusive as gratuitas.

Como reconhecer que está funcionando

Os clientes aceitam o total promocional e o troco. No exemplo de sete morangos com leve 3 pague 2, mais dois arrozes, o total é R$31; para R$50 de pagamento, o troco é R$19.

05 Automatizar o delivery

Desbloqueie o bairro e deixe a busca encontrar a rota de cada entrega.

  1. Após comprar Sistema de promoções, junte R$370 e compre Delivery Online. Prefira esperar até R$505 ou mais: sobram R$135, suficientes para um lote de cada produto. Essa reserva é uma recomendação do guia, não uma exigência do upgrade.
  2. Mantenha Principal com o código único da etapa 02. Ele detecta o primeiro pedido e calcula a rota automaticamente, sem mudar o código.
  3. Deixe o arquivo Delivery criado pelo jogo parado. Não use Rodar todos: somente Principal deve executar o código único.
  4. Acompanhe o mapa até três chegadas concluídas. A rota aceita inicia a viagem; o prêmio vem somente na chegada.

Copiar o código único

A função buscar() do código único reutiliza o exemplo BFS do projeto. Você não precisa de um segundo arquivo em execução.

Por que funciona em mapas diferentes?

A busca em largura (BFS) visita as ruas livres, guarda de onde chegou a cada posição e reconstrói o caminho até o destino. O script inclui origem e destino, avança uma célula por vez e não repete posições. As coordenadas seguem [linha, coluna]; 1 é rua, 0 é terreno e 2 é bloqueio.

Cada chegada rende R$40. O próximo pedido aparece após 15 segundos de tempo ativo, além do tempo da viagem. Não há ganhos offline. As três entregas rendem R$120 no total, sem contar os ganhos e gastos do mercado.
O delivery está parado

Confira a compra do upgrade e o estado do arquivo Principal na IDE. Durante a viagem e o intervalo entre pedidos, entrega_atual() não retorna um pedido; o script espera normalmente. Não use input() ou send() para navegar. Os comandos antigos get_deliveries() e declare_profit() foram aposentados.

06 Conferir a conclusão

Você completou o conteúdo ativo quando estes objetivos acontecerem no jogo.

  • Recebeu “Desafio Mercado Automatizado concluído!”.
  • Comprou Troco automático e Sistema de promoções, com atendimentos corretos.
  • Comprou Delivery Online e concluiu três entregas.
  • Recebeu “Desafio Delivery concluído: três entregas válidas! A automação pode continuar.”.
Não há botão final ativo nesta versão. ActiveExperience.gd desativa o fluxo de conclusão e só habilita três upgrades. O “Zerar” de cinco diamantes permanece no catálogo legado, mas está fora da experiência ativa. As entregas atuais dão dinheiro, não diamantes.

Depois da última entrega

A automação pode continuar. Este guia não altera o save, não libera menus secretos e não força a flag interna de jogo concluído. Ele cobre os objetivos que o código atual oferece ao jogador.

O mercado parou de receber clientes

Confira o estoque e o saldo. O jogo só gera pedidos de produtos disponíveis. O script tenta repor itens abaixo do mínimo quando há dinheiro para um lote. Se você gastou a reserva nos upgrades e o caixa ficou baixo, mantenha o código único rodando para receber R$40 por chegada e financiar novas reposições. Antes do delivery, preserve o saldo para lotes e adie upgrades se necessário.

O código apresenta erro ou os clientes recusam

Copie o bloco inteiro com os espaços de indentação. Use a linguagem Python-like do jogo. Pare scripts antigos: duas automações lendo input() disputam o mesmo pedido. Leia o erro no terminal e compare o arquivo com o código integral da etapa 02.

Fontes: experiência ativa, restrições de compra, condições de conclusão.
